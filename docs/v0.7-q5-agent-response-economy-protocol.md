# v0.7 Q5 crash-safe agent-response economy

Status: frozen after current-head topology audit and corpus generation, before
fresh baseline execution or production change.

## User boundary and observed topology

Agents should not pay an extra reasoning turn to discover that a final answer
must repeat exact facts Gnomon already computed. Humans should see the source,
gate, conditional consequence, primary-preservation, and automation boundary
without a repair-only conversation.

The latest four-case Q3 Evidence probe used the minimum one Gnomon product call
per case, but three final submissions were rejected once because their prose
omitted an exact validated `source.reference`. Each repair reused the artifact
and changed prose only. The run therefore used 11 final-agent requests instead
of the eight-request lower bound, plus four cold compiler requests. This is a
general response-contract defect: the compact publication contains the facts,
but does not collect the exact human-visible obligations into one bounded
checklist.

## Frozen arms and safety envelope

Use ContextBench `run_surfaces`, Evidence, DeepSeek
`deepseek-v4-flash-0731` through Engy, compiled routing, engine baseline,
temperature zero, reasoning effort none, `jobs=1`, 180-second request timeout,
120-second tool timeout, two provider retries, and two bounded infrastructure
retries. Keep append-only attempts, atomic observations, strict run identity,
and every failure in the denominator.

For each corpus run a cold lane into an empty receipt directory, then a warm
lane against exactly those immutable receipts. Baseline and candidate use new
output directories. Report compiler receipt-generation calls, final-agent
model requests, transport attempts, prompt/completion tokens, Gnomon product
calls, repair-only final-agent turns, stage latency, and response bytes
separately. Cached receipt metadata is not current-run cost.

The candidate may only add a compact, deterministic human-response checklist
whose values are copied from already published context dispositions and
authority fields. It may not alter forecasts, scenarios, support, admission,
selection, sources, gates, context claims, tool schemas, or submission
validation. Empty checklist sections must not create new obligations.

## Development and confirmation gates

- 4/4 completion in every lane; zero leakage; exact immutable-primary and
  publication identity; exact disposition and typed-relationship preservation.
- Exact preservation of every applicable validated source reference, rejection
  gate code, conditional consequence, primary-preservation statement, interval
  limit, and automation limit in final agent prose.
- One Gnomon product call per case, zero redundant product calls, and no
  compiler call on the warm lane.
- At least 25% fewer final-agent model requests and prompt tokens than baseline
  in both cold and warm development. Warm end-to-end model requests and prompt
  tokens must also fall at least 25%; cold compiler work is reported separately
  and must not increase.
- Zero repair-only final-agent turns for checklist facts. Provider retries are
  failures/cost, not savings.
- No material stage p95 latency regression above 10%, unless the absolute
  difference is below one second.
- Existing strict resume-identity and append-only-attempt tests pass. Add a
  deterministic cross-invocation fault test proving a failed row alone reruns,
  completed rows remain byte-identical, prior attempts remain visible, and
  resumed usage counts only new calls. ContextCacheBench retains exact forecast
  and artifact parity, 100% receipt/assessment hits, and its payload gates.
- The canonical MCP tool list, required inputs, inline observations,
  executable repair calls, response envelopes, self-check, and machine-readable
  frequency guidance remain discoverable.
- The exact candidate must repeat all gates on untouched confirmation, pass
  focused tests, actual final-response inspection, and the full TSFM-isolated
  suite. Otherwise revise once or retain a documented no-build.
