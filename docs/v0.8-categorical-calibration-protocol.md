# v0.8 categorical-state calibration protocol

Status: frozen before changing the production interval implementation.

## Question

Gnomon's categorical-state candidate currently calibrates every future state
from one pooled set of expanding-origin replay errors.  This is conservative,
but an error observed under a noisy state can make every quiet-state interval
unnecessarily wide.  The proposed treatment may use errors from the matching
state only when at least eight prefix-only replay errors exist.  Sparse and
unseen states must retain the pooled fallback.

The change may affect interval offsets and the median residual correction.  It
must not affect candidate admission, support, automation eligibility, the
immutable primary, or the point estimator fitted before calibration.

## Frozen prospective matrix

`benchmarks/categoricalcalibrationbench/run.py` generates 30 cases in each of
six families from seed `2026090203`: balanced state effects, state-dependent
noise, seasonal state interactions, irrelevant state labels, sparse future
states, and unseen future states.  Each case has 96 visible observations and
16 future observations.  The candidate receives only visible target/state
pairs, the already-known future state schedule, and timestamp placeholders.
Future targets are scored only after the candidate returns.

Run the unchanged implementation first and retain it as the reference.  Run
the treatment at the next revision with the exact seed and case matrix.  Both
runs are sequential, append one JSON checkpoint per case, and are resumable.

## Frozen gates

- 180/180 cases complete and no future target reaches the forecaster;
- every emitted q10/q50/q90 triple is finite and ordered;
- admission, support, automation, and primary-preservation decisions exactly
  match the reference on every case;
- sparse and unseen families remain byte-equivalent numerically;
- aggregate WIS does not worsen;
- no family median WIS worsens by more than 2%;
- state-dependent-noise median WIS improves by at least 5%; and
- aggregate central-80% coverage remains within 10 percentage points of 80%.

Failure preserves the current pooled implementation.  Success supports only
state-conditioned calibration with the eight-error fallback; it does not
promote any candidate or widen automation authority.
