# v0.7 external evaluation intake

Status: preregistered intake for the active v0.7 forecast-quality loop.

## Source and use

An external agent evaluated the published `gnomon-forecast==0.5.0` wheel on
2026-08-30 in a clean Python 3.12 environment. It used analytically generated
series and two messy operational series. The report is diagnostic evidence,
not proof that every finding remains present on the current branch.

Each finding must first be reproduced on the exact clean v0.7 head. Original
fixtures are preferred when available. Independently regenerated cases must
be labelled as such. Neither fixture identity nor expected output may enter
runtime behavior. A finding that does not reproduce is closed with retained
evidence; it is not "fixed" speculatively.

The main loop keeps one active implementation issue. This intake does not
authorize parallel edits to selection, support, temporal reasoning, or agent
surface code while another iteration owns that boundary.

## Pre-emption order

After the current Q1 production-selector baseline is retained, run two
current-head reproduction smokes before any Q1 production change.

### S1 — Decision input integrity

Reported defects: utilities with unknown scenario keys silently score zero;
a flat utilities object raises an internal exception; exact utility ties still
select an action.

User outcome: an agent must never act because malformed or non-identifying
utilities were converted into an apparently supported decision. A human must
receive a precise repair rather than a false choice or an internal-error
message.

Freeze valid, missing-action, unknown-scenario, mixed-scenario, flat-value,
non-numeric, empty, infeasible, and exact-tie cases before implementation.
If the defects reproduce, S1 pre-empts Q1 production work.

Promotion requires:

- malformed shape and non-numeric values return a typed caller error;
- every feasible action either supplies the required scenario payoffs or no
  action is selected;
- utility scenario keys are validated against the governed probability keys;
- zero matched payoff keys cannot produce a selection;
- an exact feasible-action tie returns `selected: null` with an explicit
  inconclusive reason;
- the response includes an executable repair call or argument patch;
- valid, non-tied decisions retain their previous arithmetic and selection;
- no action is executed by the evaluation verb.

### S2 — Bounded timestamp jitter

Reported defect: one-second cron drift on a 20-minute series is refused by
strict and safe ingestion, while aggressive snapping counts nearly every
timestamp against the same ceiling as imputed values.

User outcome: agents can submit ordinary operational telemetry without
building a resampler, while humans can distinguish harmless time alignment
from invented observations and genuine outages.

Freeze exact-grid controls, bounded cron and scrape jitter, offsets near the
tolerance boundary, phase-shifted grids, collisions, reordered points, mixed
cadence, and real gaps before implementation. If the defect reproduces, S2
pre-empts Q1 after S1.

Promotion requires:

- a cadence-relative tolerance and grid phase are deterministic and visible;
- only timestamps within the frozen bound are snapped;
- snapping cannot merge observations, change values, hide a gap, or reorder
  observations;
- snap counts and maximum displacement are disclosed separately from filled,
  dropped, or conflict-resolved values;
- bounded snaps do not consume the invented-value repair ceiling;
- exact clean grids remain byte-identical;
- genuine outage gaps and ambiguous or mixed cadence still fail typed;
- `off`, `safe`, `aggressive`, CLI, MCP, inspect, and forecast semantics are
  tested explicitly rather than changed accidentally.

## Findings absorbed by existing priorities

### Q1 — Forecast admission and support

Current-head reproduction must cover:

- whether a historical-mean reference is missing from the mandatory baseline
  set and therefore inflates improvement on stationary noise;
- whether a protocol-complete result can emit high-confidence prose at zero
  or immaterial gain;
- whether a long-horizon degraded fallback exposes actionable breach
  probabilities or threshold conclusions;
- whether seasonal-period error or fold-starved seasonal admission causes
  harmful departures from last-value.

These are separate experiments inside Q1. A historical mean must be evaluated
as an explicit baseline; relabelling a tunable candidate as a baseline without
measuring its selection effects is not sufficient. Protocol adequacy,
demonstrated forecast skill, and calibrated uncertainty remain separate
claims. Sub-supported or horizon-split rows may be shown for orientation but
cannot carry an actionable threshold probability.

Additional Q1 promotion gates:

- IID level cases show no material claimed skill over an appropriate level
  baseline and do not extrapolate a selected spurious trend as high
  confidence;
- honest baseline strengthening does not regress trend, seasonal,
  intermittent, or short-history families beyond their frozen bounds;
- headline wording agrees with selected model, measured gain, support, and
  calibration evidence;
- every unavailable threshold probability is typed consistently across the
  forecast artifact, brief, decision, and monitor surfaces.

### Q2 — Seasonal trend descriptions

Add additive and multiplicative seasonal upward, downward, and zero-trend
cases; noisy non-seasonal trends; genuine plateaus; and changepoint controls
to the property-stratified held-out corpus.

Promotion additionally requires direction, slope, uncertainty, support, and
automation eligibility to agree. A detected but unmodelled seasonal component
cannot yield an automation-eligible `constant` label. When the requested trend
is not identifiable after the admitted adjustment, the typed answer abstains
instead of substituting a level or raw-slope claim.

### Q5 — Agent surface and orchestration

The published 0.5.0 claim that MCP exposed only three verbs is stale on the
current branch: current-head validation must confirm the canonical tool list
and exercise each production verb rather than rebuild the surface. Required
inputs, inline observations, repair calls, response-envelope consistency, and
machine-readable frequency guidance remain discoverability checks within Q5.

## Additional queued issue

### Q6 — Regime-aware anomaly behavior

Reported defects: an investigation re-reports a detected level shift as many
post-shift anomalies, and a large spike contaminates the next forecast so the
return to normal is flagged as another anomaly.

This is queued after S1, S2, Q1, and Q2 unless reproduction reveals an
automation-eligible false alert, which permits safety pre-emption.

Promotion requires exact changepoint preservation, event-level anomaly recall
non-inferiority, improved event-level precision, no repeated alerts explained
by an admitted regime shift, no rebound duplicate after an isolated spike,
and explicit behavior for labelled and unlabelled detector selection.

## Lower-priority verification register

- Reassess seasonal-period selection under changepoints, harmonics, weak
  cycles, neighboring periods, and no-season controls as part of Q1/Q2.
- Reassess `route` after current outcome-routing changes; a no-project result
  may remain abstaining, but cost and next action must be useful.
- Verify structured repair options against the actual error, candidate input
  syntax consistency, output extension/content agreement, response envelopes,
  self-check discoverability, general frequency patterns, and
  frequency-relevant repair suggestions.

Polish cannot pre-empt a correctness, safety, forecast-skill, or crash-safety
iteration unless it prevents an agent from executing the documented repair.

## Final confirmation

After all reproduced findings have a promote, reject, or non-reproduction
decision, run a clean-wheel smoke in an isolated Python 3.12 environment. It
must include synthetic ground-truth families, bounded-jitter telemetry, a real
gap, a stationary-noise case, a long-horizon threshold case, seasonal trend,
regime shift, spike rebound, valid and malformed decisions, MCP tool discovery,
and inline observations. Actual engine artifacts and agent-readable briefs are
inspected; aggregate test counts alone do not close the intake.
