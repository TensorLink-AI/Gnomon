# Gnomon v0.7 exact-candidate final release gate

Status: frozen before versioned candidate validation.

## User boundary

The release is ready only if a clean 0.7.0 installation gives agents the same
typed forecasts, relationships, abstentions, recovery guidance, and authority
limits validated in the development tree. Humans must be able to inspect the
primary, selected path, support, provenance, warnings, and automation boundary
without relying on aggregate scores.

The release candidate includes only the 0.7.0 metadata/runtime stamp and the
already checkpointed S1, S2, Q1–Q6 production changes. Benchmark task names,
labels, answer choices, hidden futures, and source identities are not runtime
inputs. Aggregate evidence commits after the candidate do not change product
code.

## Execution order and resource policy

Record a clean candidate commit before executing data. Run the following small
shards sequentially with `jobs=1` or `max-parallel=1`, atomic checkpoints,
bounded row retries, 180-second provider requests, 120-second MCP calls, and a
15-minute CiK case timeout. A failed row remains in its denominator. Resume
only into the identical run identity and retain all attempts. Do not start the
full suite or package smoke until all three shards are complete and their
actual outputs have been inspected.

### ContextBench agent boundary

Consume the untouched stress seed `2026083103` corpus frozen by Q5, whose case
and oracle SHA-256 values are
`ac470922a429f1eac2cba2670fa964e6b1afbfd1d489514c137789782f344485`
and `d67454311e5283b63fd054c43325efd92051e47d08a00f319d12a6c1e7b4a0e7`.
Run its four preregistered SNR, numeric-constraint, structural-false, and
structural-true cases through Evidence, DeepSeek `deepseek-v4-flash-0731`
through Engy, compiled routing, engine baseline, temperature zero, reasoning
none, and a new receipt directory. The engine baseline and context surface are
the matched pair. Require 4/4 completion, exact publication and immutable
primary parity, zero leakage, one product call per case, exact source/gate/
consequence/automation preservation, and exact preservation of every exposed
typed `no_distinct_numeric_path` relationship.

### TemporalBench

Run two rows from each of T2 and T4, offsets 38–39 within each tier, from the
retained official data snapshot. Run a matched direct control and Evidence
`gnomon-mcp` arm using the same DeepSeek/Engy endpoint, temperature zero,
reasoning none, fresh context and question receipts, and the same bounded retry
policy. Require 4/4 row accounting in both arms, no future leakage, exact
engine-to-agent canonical-answer preservation wherever an engine answer is
returned, exact immutable-primary preservation, and complete separation of
forecast score, choice usefulness, support coverage, topology, and cost. This
four-row shard is a behavior/regression check, not a performance claim.

### CiK

Run untouched seed `7044` for `SensorTrendAccumulationTask`, `SensorSpikeTask`,
and `ElectricityIncreaseInPredictionWithDistractorWithDates` through Evidence
and `publication_best_effort`, DeepSeek/Engy, 50 samples, no result cache, and
one disposable case at a time. Compare the selected publication with its own
immutable primary using only retained post-forecast diagnostics. Require 3/3
accounting, zero primary-immutability failures, no automation-eligible
recommendation, a complete selection contract, and exact preservation of any
withheld prior or typed relationship. Proper scores are descriptive on this
three-task shard and cannot support a universal CiK claim.

## Clean-wheel and repository gates

Build wheel and sdist from the exact candidate and install the wheel without
editable source into an isolated Python 3.12 environment. Verify distribution,
CLI, runtime artifact, ID, and MCP server versions are all `0.7.0`; run MCP
initialize and tool discovery; then execute installed-package smoke covering
synthetic ground-truth families, bounded jitter, one real gap, stationary
noise, long-horizon threshold disclosure, seasonal trend coherence, regime
shift, spike rebound, valid and malformed decisions, inline observations, and
structured recovery. Inspect engine JSON/publication artifacts and agent briefs
for the primary, support, provenance, warnings, relationship, and automation
boundary.

After that smoke is green, run the entire repository suite with
`GNOMON_TSFM_SANDBOX_ROOT=/tmp/gnomon-empty-tsfm-root`. Push only intended
commits, verify CI on the exact proposed head across supported Python versions,
and create tag `v0.7.0` only when local evidence and CI are green. The tag must
point at the exact release commit. `docs/astrid-btc-agent-plan.md` and all other
pre-existing untracked files remain outside the release.

## Decision

Recommend release only when every row is accounted for, every safety invariant
is exact, actual outputs are inspected, the clean wheel is self-consistent,
the isolated full suite is green, and exact-head CI is green. Otherwise retain
the candidate untagged, record the failure, and revise only a general
production defect.
