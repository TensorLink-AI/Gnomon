# Operational window semantics protocol

Status: frozen before implementation on 2026-09-03.

This prospective check covers an agent/compiler boundary with direct safety
consequences: translating a stated operational interval onto the host's
forecast grid. It contains no future target observations and does not measure
forecast accuracy.

The frozen convention is:

- `between START and END` and `from START until END` are half-open `[START, END)`;
- `from START through END` is closed `[START, END]`;
- one exact start plus an exact duration remains half-open;
- the ambiguous connector `to`, approximate endpoints, wrong-target text, and
  windows that do not begin after the cutoff are refused.

The public event representation remains an inclusive pair of host-grid rows.
Therefore a half-open source interval is normalized to the last covered host
timestamp, with the source wording retained in the claim. The parser may not
consult realized outcomes, task names, or benchmark labels.

Run the frozen matrix with:

```bash
python -m benchmarks.windowsemanticsbench.run \
  --output results/window-semantics.json
```

Promotion requires all eight cases to be exact, deterministic execution with
no LLM call, and zero use of future target observations. Existing duration
semantics and the broader test suite must remain green.
