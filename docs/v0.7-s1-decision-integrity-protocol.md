# S1 protocol: decision-input integrity

Status: preregistered before the current-head reproduction or production fix.

## User hypothesis

Malformed, incomplete, or non-identifying utilities cannot select an action.
An agent receives a typed, executable repair before a forecast is spent; a
human sees an inconclusive decision when valid utilities do not distinguish
the feasible actions. Valid non-tied arithmetic remains unchanged, and
evaluation never executes an action.

## Frozen cases

Every case uses the same governed scenario names, `exceed` and `no_exceed`:

1. complete, numeric, non-tied utilities — select the higher expected-utility
   feasible action;
2. missing feasible action — typed rejection;
3. missing scenario payoff — typed rejection;
4. unknown scenario keys only — typed rejection;
5. complete required scenarios mixed with an unknown key — typed rejection;
6. flat action payoff instead of an action-to-scenario mapping — typed
   rejection;
7. non-numeric payoff — typed rejection;
8. empty utility object — typed rejection while feasible actions exist;
9. an infeasible action with no utility row plus one complete feasible action
   — select the feasible action;
10. exact expected-utility tie — select nothing and report an explicit
    inconclusive tie;
11. no feasible action — select nothing and preserve the existing unsupported
    constraint result.

The corpus lives in `benchmarks/decisioninputbench/run.py`. Case identities and
expected outcomes are benchmark assertions only and never enter production
code.

## Frozen gates

- every case terminates without an internal exception;
- malformed matrices return `INVALID_UTILITIES`, include the specific shape or
  key problem, and provide a ready-to-use `gnomon_decide` utility patch;
- every feasible action has exactly the governed scenario keys; unknown action
  and scenario keys are rejected rather than ignored or scored at zero;
- payoffs are finite real numbers; booleans, strings, NaN, and infinity are
  invalid;
- no rejected or tied case selects an action;
- an exact tie returns `selected: null`, support `inconclusive`, reason code
  `utility_tie`, and zero selection margin;
- the valid non-tied case preserves its expected utilities, selected action,
  decision rule, and supported status;
- incomplete utilities for an explicitly infeasible action are not required;
- no-feasible-action behavior remains unsupported with no selection;
- the public `gnomon_decide` boundary validates utilities before forecast work;
- focused operator, macro, tool-surface, decision-artifact, and response-contract
  tests pass.

The reproduction and candidate use the identical frozen cases. A failure is
priced in the denominator. S1 is promoted only when every safety gate passes;
there is no accuracy trade that can excuse an unsafe selection.
