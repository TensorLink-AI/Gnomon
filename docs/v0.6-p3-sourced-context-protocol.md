# P3 protocol: sourced context that remains auditable at the answer boundary

Status: preregistered before the I003 production change or fresh boundary run.

## User hypothesis

When an agent supplies a dated plan, calendar entry, log, or document, Gnomon
should turn the relevant text into a validated context receipt and preserve
the evidence chain through the compact publication. The agent should be able
to explain which source was considered and whether it changed the selected
path; a human should not need to search an internal artifact merely to identify
the cited source.

This iteration keeps three claims separate:

1. **Extraction:** the compiler found the right source text and did not invent
   events.
2. **Engine use:** the numeric gate applied, rejected, or retained that event
   as a scenario without leakage or mutation of the immutable primary.
3. **Answer preservation:** the final agent response retained the source
   identity and the engine's typed relationship to the primary.

Passing one layer does not imply either of the others.

## Frozen evidence and gap

Historical evidence is diagnostic because it predates this iteration:

- the 80-case naturalistic-prose compiled run at
  `results/contextbench-naturalistic-20260829-compiled-deepseek` completed all
  rows with compiler event precision `1.0`, event recall `0.9985`, zero false
  events, and positive mean context sMAPE lift in both true-influence families;
- retained ContextBench stress runs show zero temporal leakage and preserve
  the immutable primary; and
- the four-case Evidence/DeepSeek boundary run at
  `results/contextbench-stress-loop-20260829-agent-boundary-evidence-final`
  preserves the typed `no_distinct_numeric_path` relationship where the
  primary already reflects the claimed structural change.

Manual inspection also found the active product gap. The full artifact retains
the content-addressed receipt, verbatim evidence quote, `known_at`, and source
reference. The compact publication reduces an event disposition to an opaque
context ID and “See the immutable context outcome receipt.” This is engine
contract completeness without useful agent/human provenance preservation.

## Change boundary

The only permitted production change in I003 is a bounded public provenance
projection:

- derive evidence only from validated `ContextEvent` fields;
- attach event ID, source type, source reference, knowledge time, receipt ID,
  and verbatim evidence quote to the public context outcome;
- carry that same evidence into the matching sealed publication disposition;
- never infer a source, quote, effect magnitude, or application state; and
- leave forecasts, admission, support, scenario selection, and automation
  policy unchanged.

Missing provenance remains visibly missing. A model-authored assertion cannot
upgrade itself to a verifiable source through this projection.

## Frozen validation

### Contract tests

Focused tests must prove all of the following:

- applied, scenario-only, and rejected context outcomes retain the validated
  source fields and exact quote;
- unrelated-series context remains `not_considered` and does not leak source
  text into the wrong result;
- publication dispositions join provenance by exact context/event ID;
- publication seals authenticate the added provenance and fail after
  tampering;
- missing sources and quotes do not produce invented placeholders; and
- existing relationship, primary-immutability, automation, and scenario
  consequence contracts still pass.

### Matched engine smoke

Use the existing naturalistic ContextBench corpus only as a fresh current-code
regression smoke, not as a new real-world superiority claim. Select two cases
from each of `future_covariate`, `repeated_event`, `irrelevant`, and
`prior_only`. Run the compiled-context arm with DeepSeek through Engy,
temperature `0`, `jobs=1`, two bounded infrastructure retries, 180-second
request timeout, and resumable output. Every terminal row stays in the
denominator.

The smoke passes only if:

- all eight cases terminate and at least one applied, one rejected, and one
  scenario/no-numeric-change result are represented;
- compiler event precision is at least `0.99`, event recall is at least
  `0.95`, and no false event is emitted;
- every successful forecast has publication parity and zero temporal leakage;
- the selected forecast, immutable primary, support, admission disposition,
  and automation eligibility match the pre-change arm exactly; and
- every considered event with a validated source has a matching public
  provenance record with exact source reference, `known_at`, and quote.

### Agent-boundary probe

After engine and publication tests pass, run a four-case surface shard through
the Evidence profile and DeepSeek through Engy with `baseline-mode=engine`,
`routing-policy=compiled`, `jobs=1`, temperature `0`, bounded retries, tool
timeout 120 seconds, and resumable checkpoints. Select representative applied,
rejected, scenario, and `no_distinct_numeric_path` cases without consulting
their sealed futures during execution.

The agent probe passes only if every row:

- terminates with publication parity and zero leakage;
- preserves canonical-primary and automation-authority fields;
- preserves `no_distinct_numeric_path` when present;
- names or exactly projects the validated source reference for considered
  context, without inventing a source; and
- keeps engine provenance completeness and final-response preservation as
  separate reported rates.

## Decision rule

Promote the projection only if the contract tests, matched engine smoke, and
agent-boundary probe all pass with exact invariant preservation. Revise only
the general provenance boundary if a failure is source-projection related.
Reject and remove the change if it alters numeric behavior, increases
leakage, weakens source validation, or requires benchmark IDs, families,
labels, or oracle fields at runtime.

The naturalistic corpus is synthetic data expressed as natural prose. It can
validate extraction and boundary behavior but cannot establish that real
organizations supply useful context at the same rate. That external-validity
risk remains explicit in the I003 decision.

## Post-probe revision record

This section was written after the frozen probe exposed defects. It is an
audit record, not a claim that the following criteria were preregistered.

The provenance projection itself passed its contract tests, but the first
fresh agent probe showed that the compiler had assigned `override:*` authority
to ordinary dated deployment windows whose quotes stated no override value.
The numeric lane correctly rejected those events. That was safe but
semantically wrong: the grounded schedule should have remained available to
the fold-safe qualitative-event lane. A second probe then showed that an
admitted future covariate was present in the engine artifact but absent from
the agent host's typed context execution, allowing the answer to say no
context had been applied. Finally, the full suite showed that exact provenance
was repeated once per event in compact briefs and exceeded the wire budget.

I003 therefore entered a visible `revise` sub-iteration. The revised changes
were limited to general boundaries:

- a proposed numeric namespace survives only when Gnomon's literal parser can
  verify its numeric claim; a quote with no non-temporal number is demoted to
  its grounded qualitative event type, while an unparsed number remains in
  the fail-closed numeric lane;
- admitted covariates publish their engine-owned relationship to the primary
  and their evidence authority, and the agent host preserves those facts;
- an accepted agent answer must state an applied/admitted relationship
  affirmatively; and
- compact wire projections group repeated identical provenance while keeping
  exact counts, one exact representative, and the sealed full-receipt path.

The original exact-disposition parity subgate does not pass on final code:
three of eight rows move from `rejected` to nonnumeric `scenario_only` as a
direct consequence of the type repair. The revised decision therefore
requires exact forecast, sMAPE, application, immutable-primary, automation,
publication-parity, and leakage parity; no newly applied event; the three
typed changes must be exactly the expected rejection-to-scenario demotions;
and all final agent-preservation gates must pass. This post-observation gate
cannot retroactively validate the original protocol. The retained decision
reports both results separately.
