# V0.6 P6 joint multi-horizon uncertainty protocol

Status: frozen before production changes on 2026-08-30.

## User hypothesis

When an agent or human asks whether any forecast step breaches a limit or what
the horizon total may be, Gnomon should answer both from one coherent set of
joint paths. Marginal intervals remain useful per step, but they must not be
silently multiplied or summed as if adjacent leads were independent.

## Audit finding and bounded change

The production threshold path already estimates any-step and first-step breach
risk by replaying aligned residual trajectories reserved after selection.
Scarce histories degrade to a disclosed blocked bootstrap and, when necessary,
an explicitly best-effort independence composition; only the supported aligned
path can govern automation. BreachBench previously demonstrated material
decision-cost gains, but its retained runs predate the current v0.6 head.

The same forecast paths are currently discarded after maximum and first-breach
statistics are computed. The treatment may only add a `cumulative_horizon`
projection to the existing `horizon_event` containing:

- the sum of the published q50 path;
- empirical mean and median totals across the same joint forecast paths;
- an empirical 80% total interval;
- path count, basis, dependence-preservation flag, support, and assumptions.

No point, marginal quantile, per-step probability, any-breach probability,
first-breach distribution, support tier, or action policy may change. No new
caller parameter or estimator threshold is introduced. When no paths exist,
the cumulative projection must say unavailable rather than sum marginal bands.

## Frozen current-head corpus

Use 60 deterministic, non-overlapping realised-future windows from the checked-
in BreachBench real telemetry corpus, generator seed 20260906, horizon 24, and
the existing history strata (24, 48, 96, 168). Thresholds, affine
anonymisation, label-invariance checks, and real cadences are inherited from
`breachbench-generator-0.3`. Runtime sees only the visible history, cadence,
threshold, and horizon; realised futures and case labels remain runner-side.

Erratum recorded before the baseline run: the first frozen revision named
generator 0.2, while both commit `340fd32` and the current benchmark source
identify the unchanged generator as 0.3. This corrects provenance only; no
case generation rule, seed, count, threshold, or gate changed.

The baseline is the pre-change threshold artifact at commit `340fd32`, plus
its peak-step and raw independence diagnostics. Treatment is the additive
cumulative projection on the identical cases. Execution is local, serial,
resumable, with one retry and a 60-second case timeout.

## Frozen gates

All incomplete or unavailable rows remain in denominators.

- **Completion:** 60/60 baseline and 60/60 treatment engine cases complete.
- **Numerical parity:** every point, q10/q50/q90, per-step probability,
  any-breach probability/interval, first-breach distribution, support, and
  governed/advisory action is exactly equal across arms.
- **Any-step coherence:** on every path-bearing row,
  `max(step marginal) <= P(any breach) <= min(1, sum(step marginals))` when the
  dependence-preserving estimator and marginals refer to the same empirical
  sample; first-breach probabilities sum to `P(any breach)` within 1e-6.
- **Probability skill:** on dependence-preserved rows, joint any-breach Brier
  loss is non-inferior within 0.02 to the better of peak-step and raw
  independence diagnostics. Across all probability-bearing rows, governed
  policy decision cost is no worse than the better constant action.
- **Cumulative identity:** `point_total` exactly equals the sum of published
  q50 values and every empirical total is the sum of one complete joint path.
- **Cumulative usefulness:** among path-bearing rows, realised-total coverage
  of the 80% total interval is between 0.65 and 0.95; its mean width is no
  greater than the mean width from summing marginal q10/q90 endpoints.
- **Cumulative coherence:** each total interval is ordered, its median lies
  within it, and positive affine transformation by `(a, b)` maps total centre
  to `a * total + horizon * b` and width to `a * width`.
- **Fallback truth:** dependence-preserved is true only for aligned real paths;
  bootstrap and independence lanes name their assumptions and cannot be
  automation-eligible merely because a total exists.
- **No widening:** all marginal interval widths are byte-identical to baseline.
- **Agent surface:** compact threshold output retains cumulative point, median,
  interval, support, basis, and dependence flag, or names the complete artifact
  path if bounded output omits detail.

The probability-skill gate is a non-inferiority requirement because P6 does not
change the already-governed breach estimator. The new cumulative projection is
promoted only if its own usefulness/coherence gates and all existing safety
gates pass.

## Execution and inspection

One atomic JSON row is written per case; reruns skip complete matching rows.
The retained identity includes corpus hash, generator version, seed, commit,
dirty state, jobs, retry/timeout policy, and row hashes. Inspect one supported
aligned-path case, one blocked-bootstrap case, one independence-composed case,
and any unavailable case. Engine completeness and any later agent preservation
are scored separately.

## Kill and no-build rules

Reject or revise if totals are constructed by summing marginal quantiles, if
the additive projection changes existing risk or decisions, if held-out totals
are read at runtime, if total intervals miss the frozen coverage/usefulness
band, or if weak paths gain automation authority. Do not tune residual gates,
bootstrap size/block, quantiles, or corpus after inspecting outcomes. If the
projection fails, retain the existing any-breach executable and record
cumulative totals as no-build.
