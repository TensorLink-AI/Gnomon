# v0.7 Q3 context recall at fixed precision

Status: frozen before fresh corpora, baseline execution, or production change.

## User boundary

Agents should discover and preserve genuinely usable dated context often
enough to improve a forecast. Humans must be able to distinguish four separate
outcomes: compiler proposal, numerically admitted effect, non-automatable
scenario, and rejected or out-of-scope evidence. Scenario yield is useful but
is never counted as numeric admission recall.

## Frozen development and confirmation corpora

Generate after this protocol is committed:

- stress development: seed `2026083101`, four cases per stratum;
- naturalistic compiler development: seed `2026083201`, four cases per family;
- untouched stress confirmation: seed `2026083102`, eight cases per stratum;
- untouched naturalistic compiler confirmation: seed `2026083202`, ten cases
  per family.

The existing generators, formulas, sealed futures, truth states, SNR curve,
false claims, timing uncertainty, cross-entity controls, numeric claims, and
structural claims are unchanged. Stress runs use the deterministic engine
surface. Naturalistic runs use compiled routing with DeepSeek
`deepseek-v4-flash-0731` through Engy, temperature zero, `jobs=1`, atomic
resumable rows, 180-second request timeout, 120-second tool timeout where
applicable, and two bounded retries. Missing rows remain in denominators.

Generator family, seed, case ID, oracle disposition, future, effect magnitude,
and expected answer may not enter product behavior.

## Separate measures

Report, with denominators and confidence intervals where defined:

- compiler event precision, event recall, false events, invalid events, and
  source/known-time completeness;
- engine numeric admission precision and recall;
- false-influence rate, harmful admission count, leakage, publication parity,
  and immutable-primary behavior;
- complete typed engine disposition and relationship contracts;
- scenario count, scenario consequence completeness, and scenario-only
  opportunity quality, explicitly outside admission recall;
- automation-eligible admitted count and precision; and
- provider, compiler, engine, retry, call, token, and latency accounting.

Matched recall change uses the same rows in both arms. Promotion requires a
positive one-sided exact McNemar result at `p < 0.05` or a strictly positive
95% paired-bootstrap lower bound over should-influence rows. A point increase
alone is insufficient.

## Development discipline

Run both baselines before implementation. Inspect every missed
should-influence row by compiler supply, typed event class, gate code, fold
evidence, interval evidence, and scenario availability. A candidate may
change only a general production boundary implicated by those receipts. It
may not lower a threshold merely to satisfy recall, convert scenarios into
admissions, infer ungrounded timing or magnitude, or use oracle truth.

If misses lack repeatable prefix-visible numerical evidence, retain the
rejection. If a complete compiler proposal is lost at a product boundary,
repair that boundary. If a candidate has useful directional evidence but
fails automation-grade calibration, preserve it as a typed scenario and do
not count it as admitted.

## Promotion gates

Promote only if the exact candidate and untouched confirmation show:

- 100% empirical numeric admission precision and zero false influence;
- zero temporal leakage and exact canonical-primary policy;
- statistically positive matched numeric admission-recall improvement;
- no family recall regression larger than two percentage points;
- compiler precision `>= 0.99`, recall `>= 0.95`, zero false events, and no
  compiler regression relative to baseline;
- every considered event has a complete typed disposition, source evidence,
  relationship to primary, scenario consequence when applicable, and exact
  automation eligibility;
- scenario-only and automation-eligible yields are reported separately and
  never used to inflate admission recall; and
- focused tests, a bounded real-agent preservation shard, and the full suite
  isolated from machine-local TSFM supply pass.

If the development mechanism does not clear these gates, remove or disable it
and retain the evidence-backed no-build. Previously scored v0.6/v0.7 corpora
are regression diagnostics only after the mechanism is frozen.
