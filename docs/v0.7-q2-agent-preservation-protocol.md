# v0.7 Q2 agent preservation protocol

Status: frozen before the agent runner, API calls, or boundary changes.

## Boundary and cases

This is an eight-case regression shard, not a TemporalBench accuracy claim.
The six trend cases are selected by preregistered family coverage from the
fresh `8121`-`8128` confirmation cohort, before inspecting any model response:

- `additive_up-8121`;
- `multiplicative_zero-8122`;
- `noisy_down-8123`;
- `plateau_after_up-8124`;
- `unadmitted_season_zero-8125`; and
- `insufficient_cycle_up-8126`.

The two context controls reuse the frozen corpus and case IDs from the v0.6 P8
protocol:

- `stress-structural-true-0000`;
- `stress-structural-true-0001`.

The trend rows ask the production Evidence surface for a forecast and one
typed predictive trend answer with options `Upward`, `Constant`, `Downward`,
and `Uncertain`. Forecast values are never scored here; the artifact is used
to establish immutable-primary identity and to retrieve the engine's exact
temporal-answer receipt. The context rows retain their existing engine
baseline and structural relationship scorer.

## Execution

Use Evidence, DeepSeek `deepseek-v4-flash-0731` through Engy, compiled
routing/questions, engine baseline where applicable, temperature 0, reasoning
effort none, `jobs=1`, request timeout 180 seconds, MCP tool timeout 120
seconds, two transport retries, and two bounded infrastructure retries. Write
one atomic/resumable row at a time and fail closed on identity mismatch.

The trend runner may use a deterministic host receipt for its already-frozen
typed question; it must not send expected directions, support states, oracle
slopes, family names, or future observations to the compiler, engine, or
agent. Public case IDs are hashes. All actual final outcomes and tool traces
are retained for manual inspection.

## Separate gates

- **Engine completeness:** six trend artifacts and temporal-answer receipts
  complete; canonical direction, display value, support, automation flag,
  point/interval, and primary-unchanged fact are present or typed-null for an
  abstention.
- **Agent choice preservation:** final submitted trend choice equals the
  engine display value, or `Uncertain` for a genuine engine abstention, on
  6/6 rows.
- **Host contract preservation:** the final outcome exposes the canonical
  choice, exact support state, exact automation flag, and primary-unchanged
  fact together on 6/6 rows. Host projection and model authorship are reported
  separately.
- **No authority inflation:** no weak or abstained engine answer is represented
  as binding or automation-eligible.
- **Primary immutability:** every submitted forecast uses the exact Gnomon
  artifact and the temporal answer says the primary is unchanged.
- **Structural relationship:** both context engines expose the typed
  `no_distinct_numeric_path` opportunity, and both final agent responses
  preserve it exactly together with primary immutability and
  `automation_eligible=false`.
- **Topology:** all eight cases remain denominators; provider, harness, engine,
  agent, retry, token, and latency results are separate and complete.

If the engine receipt is complete but the final trend outcome omits support or
authority, fix the general deterministic host projection rather than prompt
tuning. If the model changes a canonical choice despite a complete receipt,
fix the general Evidence submission boundary and rerun the identical shard.
Do not add case-specific language or route on expected answers.
