# V0.6 P7 hierarchical reconciliation protocol

Status: frozen before production changes on 2026-08-30.

## User hypothesis and audit finding

When a user supplies additive organizational structure, an agent should not
have to add independently rounded forecasts or explain why a displayed total
disagrees with its components. Humans need one coherent planning path plus the
exact leaves, adjustment/derivation rule, support floor, and limitations.

Gnomon currently forecasts panel channels independently (with an admitted
pooled-trend candidate where appropriate) and has no forecast hierarchy input
or additive reconciliation receipt. It therefore does not falsely label an
incoherent result as reconciled, but an agent cannot request a derived total.
This is a genuine missing boundary, not a numerical bug in existing forecasts.

## Bounded candidate

The candidate may add an explicit additive hierarchy to a multi-target
forecast. A hierarchy is a caller-supplied acyclic mapping from derived parent
names to two or more exact child names. Leaves are existing forecast targets;
parents may feed higher parents but may not collide with input target names.

The first candidate is bottom-up and point-only:

- every parent q50 equals the exact sum of its direct children at each step;
- leaf forecasts, intervals, support, model selection, evidence, and order are
  byte-identical to the run without a hierarchy;
- the receipt names every edge, contributor, step, derivation, weakest leaf
  support, and immutable leaf forecast hashes;
- aggregate uncertainty is explicitly unavailable because summing marginal
  quantiles would invent a joint distribution;
- hierarchy evidence alone cannot authorize automation;
- unknown nodes, collisions, cycles, duplicate children, disconnected leaves,
  inconsistent timestamps, or a child with no forecast fail with typed repair
  guidance rather than partial arithmetic.

No statistical reconciler, fitted covariance, interval synthesis, or change to
single-target/default multi-target behavior is in scope. Promotion requires
the simple bottom-up total to earn its usefulness empirically; otherwise P7 is
recorded no-build rather than widening the candidate after outcomes are seen.

## Frozen corpus

Use 32 non-overlapping realised-future windows derived from the four checked-in
BreachBench real series, eight per source. Each visible root history is split
deterministically into three positive leaves whose values sum exactly to the
root at every timestamp. Half use stable shares and half use smooth periodic
shares; the split family is scorer-side and never reaches the forecaster. Use
history 96, horizon 24, seed 20260907, and each source's real cadence.

The control is a standalone Gnomon forecast of the visible historical root.
The candidate is the exact sum of the three leaf q50 forecasts from an
otherwise identical serial multi-target call. Realised root and leaf futures
remain scorer-side. This preimplementation counterfactual freezes whether the
bounded arithmetic is worth exposing before product code is written.

Execution is local, jobs=1, one retry, a 60-second case timeout, atomic JSON per
case, and resume only when corpus, seed, runtime commit, and runner identities
match.

## Frozen gates

All incomplete, abstained, invalid, or unavailable rows remain denominators.

- **Completion:** 32/32 root controls and 32/32 leaf batches complete.
- **Leakage:** runtime inputs contain visible histories only; realised futures,
  split family, case labels, and next shares never enter either arm.
- **Coherence:** every candidate parent q50 is exactly the sum of its children
  at every step; a deterministic nested-tree property test must also pass.
- **Leaf preservation:** hierarchy-on leaves are byte-identical to hierarchy-
  off leaves; default artifacts and IDs remain unchanged when no hierarchy is
  supplied.
- **Output skill:** candidate root MAE is no worse than 1.02 times standalone
  root MAE in every source and split-family stratum, and pooled root absolute
  error improves by at least 5%. Report paired per-case deltas and a seeded
  bootstrap 95% interval; the interval need not clear zero for this 32-case
  bounded screen, but its sign is disclosed.
- **Scale safety:** candidate root q50 remains finite, and positive input
  histories/futures cannot produce a negative aggregate merely through
  reconciliation.
- **Uncertainty truth:** no aggregate q10/q90 or coverage claim is emitted;
  the contract says `unavailable_joint_distribution` and points to the leaf
  intervals.
- **Authority:** automation eligibility is false and no leaf support tier is
  upgraded; parent support names the weakest contributing leaf.
- **Agent surface:** brief and full outputs retain the parent path, exact edges,
  leaf hashes/location, support, derivation, uncertainty status, and authority,
  or name the complete artifact path if bounded output omits bulk steps.
- **Failure behavior:** invalid graphs fail before forecasting and identify the
  offending nodes plus an executable correction.

## Inspection and decision

Inspect one stable-share win, one periodic-share win or loss, the worst paired
regression, one unavailable/abstained case if present, and invalid cycle,
collision, unknown-child, timestamp-mismatch, and nested-tree contracts.
Engine completeness and any later model-language preservation remain separate.

Promote only if every gate passes without changing the frozen corpus, share
families, thresholds, or arithmetic. If skill fails, retain independent panel
forecasts and the evaluation harness, and record hierarchy totals as no-build.
