# v0.7 Q3 structural agent-boundary probe

Status: frozen before current-head agent execution.

## Purpose

The Q3 development baselines separate complete compiler supply from
conservative engine admission. Before closing numeric recall as a no-build,
this probe verifies the remaining user boundary: a final agent response must
preserve the engine's typed relationship when an immutable primary already
reflects the claimed structural change.

Engine-contract completeness and agent-language preservation are scored
separately. A prompt cannot compensate for a missing or incorrect engine
relationship, and a complete engine artifact does not by itself prove that a
human receives the relationship.

## Gates

All four rows remain denominators.

- Engine execution completes 4/4 with exact publication identity, canonical
  primary preservation, zero temporal leakage, complete typed dispositions,
  and exact automation eligibility.
- Report how many engine responses expose
  `relationship_to_primary=no_distinct_numeric_path`; do not alter product
  behavior if the opportunity count is small or zero.
- Every exposed relationship is preserved in the final response as the fact
  that the claimed structural change has no defensibly distinct numeric path
  because the emitted immutable primary already reflects it.
- No final response says context rewrote the canonical primary or grants
  automation authority.
- Applicable source, failed-gate, scenario consequence, and interval-limit
  facts remain present.
- Agent completion is 4/4 without provider or harness failure, and request,
  token, retry, timeout, and resume accounting is complete.

Inspect every final response. If the engine contract is complete but agent
preservation fails, repair only the general Evidence projection/instruction
boundary and rerun this shard. If all gates pass, retain a boundary no-build;
do not add a redundant wrapper or tune wording to these cases.
